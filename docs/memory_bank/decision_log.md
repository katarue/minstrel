# Decision Log

Minstrelプロジェクトで確定した決定事項とその根拠の記録。

各決定はD-NN形式で連番管理する。

---

## D-001：ドメイン名は minstrel.live

**日付**: 2026年5月（プロジェクト立ち上げ時）  
**決定**: ドメインに `minstrel.live` を採用  
**根拠**: 吟遊詩人（Minstrel）というブランド名と、ライブ・コンサート（live）の意味の二重化  
**代替案**: minstrel.jp、minstrel.com  
**影響**: ブランド名「Minstrel」を中世的世界観の中核に据える方針が確定

---

## D-002：技術スタックの確定

**日付**: 2026年5月（計画策定時）  
**決定**: Next.js + Supabase + Vercel + Prefect + Claude API + twitterapi.io  
**根拠**: 個人運用で持続可能なコスト（月1,500〜2,500円想定）、既存のAI News Pipeline環境との親和性  
**影響**: フェーズ1〜2の全実装方針が確定

---

## D-003：情報源ランク制（A/B/Cランク）

**日付**: 2026年5月（計画策定時）  
**決定**: 情報源を3ランクに分類し、自動公開対象を限定する  
- Aランク（公式サイト・公式X・公式チケット販売）→ 自動公開対象  
- Bランク（2083WEB・noteまとめ等）→ 補助情報・手動確認推奨  
- Cランク（一般ユーザー投稿等）→ 発見用、公開ソースにしない

**根拠**: 「人間が見なくても事故らない仕組み」を実現するため、AIに最終判定をさせず情報源の信頼性で制御する  
**影響**: スクレイピング設計、機械検証ルール、auto_publish_eligibleフラグの設計に直結

---

## D-004：機械検証アプローチ

**日付**: 2026年5月（計画策定時）  
**決定**: AIによる「ファクトチェック」ではなく、ルールベースの「機械検証」を行う  
**根拠**: AIの判定は確率的で安定しない。ルールベースなら100%再現可能で安全  
**影響**: フェーズ2-D（機械検証）の実装内容が決定

---

## D-005：「70点の網羅性、95点の安全性」哲学

**日付**: 2026年5月（計画策定時）  
**決定**: 取りこぼしを許容し、誤掲載は絶対回避する方針  
**根拠**: 個人運営で炎上対応コストが高い、誤情報による信頼失墜の方が致命的  
**影響**: 情報源ランク制、機械検証、auto_publish_eligibleの判定厳格化

---

**日付**: 2026年5月7日

## D-026：AUTO-PUSH POLICY 有効化

**日付**: 2026年5月7日
**決定**: `.githooks/post-commit` を `git config core.hooksPath .githooks` で有効化
**根拠**: D-025 で配置済みのフックが動作テスト未実施だったため保留していた。`feature/auto-push-test` ブランチでコミット → 自動 push → `[post-commit] Pushed successfully` を確認して有効化に踏み切った。
**動作仕様**:
- `feature/*` ブランチ: コミット直後に自動 `git push origin <branch>`
- `main` / `chore/*` / その他: 自動 push なし（手動 push が必要）
- バイパス: `git commit --no-verify`（使用時は memory-bank に理由を記録）
**影響**: CLAUDE.md の AUTO-PUSH POLICY ステータスを「有効（2026-05-07〜）」に更新
